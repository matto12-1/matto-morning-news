# 데일리 문해력 신문 — 설계 문서 (Design Spec)

- **가제:** "오늘의 아침신문" (이름 미확정, 나중에 교체 가능하게 설계)
- **작성일:** 2026-07-21
- **목적:** 초등 3~6학년의 **문해력**을 매일 아침 "글 한 편 읽기 + 퀴즈"로 기른다.
- **빌드 방식:** 밤새 자율 에이전트가 로컬 완성 → 다음 날 아침 배포·자동화 연결.

---

## 1. 한 줄 정의

초등 3~6학년이 **매일 아침 짧은 글 한 편을 읽고 퀴즈로 확인**하며 문해력을 기르는, **백엔드 없는 정적 웹앱**. 콘텐츠는 Claude가 집필하고, **매일 밤 클라우드 예약 실행이 새 글 한 편을 자동 생성·배포**한다. 교사는 링크만 알려주거나 워크시트로 인쇄해 배부한다.

## 2. 사용자 & 목표

- **주 사용자(학생):** 초등 3~6학년. 하루에 딱 한 편만 읽고 푼다.
- **부 사용자(교사):** 오늘 글을 화면에 띄우거나 A4로 인쇄해 배부. 특정 날짜 글도 볼 수 있음.
- **성공 기준:**
  - 아이가 로그인·설치 없이 접속해 **3분 내에 읽기+퀴즈**를 끝낼 수 있다.
  - 교사가 **버튼 하나로 학생용/교사용(정답지) 워크시트**를 인쇄한다.
  - **매일 밤 자동으로** 새 글이 겹치지 않게 추가된다(무인).

## 3. 핵심 결정 사항 (확정)

| 항목 | 결정 |
|---|---|
| 타깃 학년 | 초등 3~6학년 |
| 읽기 난이도 | **2버전** (저학년 3~4 / 고학년 5~6), 같은 주제 |
| 콘텐츠 성격 | 알쓸신잡(상식·과학) + 문학·고전. 시의성 없는 evergreen |
| 주제 갈래 | 과학·자연·우주 / 역사·인물·문화 / 문학·고전·신화 / 우리말·사회상식 |
| 콘텐츠 저자 | **Claude가 집필** (외부 LLM·Gemini 미사용) |
| 이미지 | **없음(v1)**. Gemini 이미지 한도 소진. SVG·타이포·컬러로 신문답게. 한도 회복 후 삽화만 얹기 |
| 퀴즈 종류 | 내용 이해(사지선다·OX), 어휘(뜻 고르기·빈칸), 생각 넓히기(서술·자가채점), 보너스(가끔) |
| 채점 | **자가채점**(클라이언트). 결과 서버 전송·수집 없음 |
| 진도 저장 | **저장 안 함**(극단적 단순화). streak·localStorage 없음. 세션 내에서만 점수 표시 |
| 아카이브 | **없음**(오늘 글만 노출). 과거 글 파일은 저장소에 쌓이되 UI로 안 보임 |
| 백엔드 | **없음**. 100% 정적 |
| 콘텐츠 공개 | 브라우저가 오늘 날짜로 오늘 글 1편만 표시 |
| 매일 새 글 | **[B] 매일 밤 클라우드 예약 실행 에이전트가 1편 자동 추가** |
| 실행 주체 | **클라우드 예약 실행(cron routine) + 자동 배포** |
| 개인정보 | 수집 0. 계정 0 |

## 4. 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│  매일 밤 (클라우드 예약 실행 / cron routine)                  │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 나이틀리 생성 잡 (Claude 에이전트)                      │  │
│  │  1) topics.json(과거 주제) 읽기                         │  │
│  │  2) 안 겹치는 새 주제 1개 선정                          │  │
│  │  3) 기사(저/고 2버전)+어휘+퀴즈 집필 (스키마 준수)      │  │
│  │  4) 자동 검증 (스키마·정답 인덱스·빈 필드·금칙어)       │  │
│  │  5) content/YYYY-MM-DD.json 저장, index.json·topics 갱신│  │
│  │  6) git commit & push → 자동 배포 트리거                │  │
│  └───────────────────────────────────────────────────────┘  │
└───────────────────────────────┬─────────────────────────────┘
                                 │ (정적 파일 배포)
                                 ▼
┌─────────────────────────────────────────────────────────────┐
│  정적 사이트 (무료 호스팅: GitHub Pages / Netlify)           │
│  앱 껍데기(HTML/CSS/JS) + content/*.json                     │
│   - 브라우저가 오늘 날짜 → 오늘 글 1편 로딩·표시              │
│   - 읽기 → 퀴즈(즉시 채점) → 인쇄                            │
│   백엔드 0 · 로그인 0 · 진도저장 0                           │
└─────────────────────────────────────────────────────────────┘
```

### 4.1 기술 스택 (자율 빌드 안정성 우선)

- **프론트엔드:** **빌드 스텝 없는 바닐라** HTML + CSS + JS(ES modules). 프레임워크·번들러 없음.
  - 이유: 자율 빌드 중 의존성/빌드 실패 지점을 최소화. 정적 호스팅에 그대로 올림.
- **폰트:** Pretendard (웹폰트 또는 로컬 번들). 가독성 우선.
- **콘텐츠 형식:** 기사마다 `content/YYYY-MM-DD.json` 1개 + `content/index.json`(날짜 목록) + `content/topics.json`(중복 방지용 과거 주제 목록).
- **자동화:** Claude Code **예약 실행(cron routine)**. 나이틀리 잡은 정해진 프롬프트 + 검증 스크립트(Node).
- **호스팅/배포:** GitHub 저장소 + 무료 정적 호스팅(Pages/Netlify). push 시 자동 배포.

### 4.2 "오늘 글" 결정 로직 (클라이언트, 백엔드 없음)

1. 앱이 `content/index.json`(사용 가능한 날짜 배열) 로딩.
2. 브라우저 `오늘 날짜(YYYY-MM-DD)` 계산.
3. `오늘 날짜`와 일치하는 항목이 있으면 그 글, 없으면 **오늘 이전의 가장 최근 글**로 폴백(주말·미생성 대비).
4. 교사용: URL 쿼리 `?date=YYYY-MM-DD` 로 특정 날짜 글 직접 열람(아카이브 UI 없이도 접근).

## 5. 콘텐츠 데이터 모델

### 5.1 기사 1편 JSON 스키마 (`content/YYYY-MM-DD.json`)

```json
{
  "date": "2026-07-21",
  "issueNo": 1,
  "category": "science",
  "categoryLabel": "과학·자연·우주",
  "title": "왜 하늘은 파랄까?",
  "subtitle": "햇빛 속에 숨은 무지개 이야기",
  "readingTimeMin": { "lower": 2, "upper": 3 },
  "body": {
    "lower": "문단 배열. 저학년(3~4) 쉬운 말, 짧은 문장.\n\n문단 사이는 빈 줄.",
    "upper": "문단 배열. 고학년(5~6) 조금 더 깊고 긴 설명."
  },
  "vocab": [
    { "word": "산란", "meaning": "빛이 여러 방향으로 흩어지는 것" }
  ],
  "quiz": {
    "comprehension": [
      {
        "type": "mc",
        "question": "하늘이 파랗게 보이는 까닭은?",
        "choices": ["…", "…", "…", "…"],
        "answerIndex": 2,
        "explain": "파란빛이 가장 많이 흩어지기 때문이에요."
      },
      {
        "type": "ox",
        "question": "노을이 붉은 것도 빛의 산란과 관련이 있다.",
        "answer": true,
        "explain": "저녁엔 빛이 더 두꺼운 공기를 지나며 붉은빛이 남아요."
      }
    ],
    "vocab": [
      {
        "type": "meaning",
        "question": "'산란'의 뜻으로 알맞은 것은?",
        "choices": ["…", "…", "…", "…"],
        "answerIndex": 0
      },
      {
        "type": "cloze",
        "question": "빛이 공기 알갱이에 부딪혀 흩어지는 것을 ___이라고 한다.",
        "answer": "산란",
        "acceptable": ["산란"]
      }
    ],
    "think": {
      "question": "만약 공기가 하나도 없다면 하늘은 무슨 색으로 보일까? 왜 그렇게 생각해?",
      "modelAnswer": "검은색에 가깝다. 빛을 흩어줄 공기 알갱이가 없기 때문."
    },
    "bonus": null
  },
  "source": "일반 과학 상식(빛의 레일리 산란)을 초등 수준으로 재구성. 특정 저작물 인용 없음.",
  "illustration": null
}
```

**필드 규칙**
- `category` ∈ `science | history | literature | language`.
- `body.lower`/`body.upper`: 같은 주제, 다른 난이도. 저학년은 더 짧고 쉬운 어휘·짧은 문장.
- `vocab`: 3~5개. 본문에 실제 등장하는 낱말. 본문에서 하이라이트+툴팁으로 연결.
- `quiz.comprehension`: 3~4문항(mc/ox 혼합).
- `quiz.vocab`: 2~3문항(meaning=객관식 / cloze=빈칸, `acceptable` 배열로 표준화 채점).
- `quiz.think`: 1개. 자동채점 안 함. 학생 답 입력 후 `modelAnswer` 토글로 비교.
- `quiz.bonus`: 가끔만(없으면 null). 타입: `order`(문장 순서), `match`(속담·사자성어 연결), `factopinion`(사실/의견 구분).
- `illustration`: v1은 항상 null. 한도 회복 후 이미지 경로로 채움.

### 5.2 인덱스 & 중복방지 파일

- `content/index.json` — `["2026-07-21", "2026-07-22", …]` (오름차순 날짜 배열, 나이틀리 잡이 갱신).
- `content/topics.json` — `[{ "date": "2026-07-21", "category": "science", "title": "왜 하늘은 파랄까?", "keywords": ["빛","산란","무지개"] }, …]`. **나이틀리 잡이 새 주제를 고를 때 이 목록과 겹치지 않게** 검사.

## 6. 콘텐츠 집필 가이드 (Claude가 지킬 규칙)

- **안전:** 4개 갈래의 안전한 주제만. 폭력·범죄·성·정치갈등·특정 종교/집단 비하 금지(금칙어 검증으로 2차 차단).
- **사실성:** 검증 가능한 상식·역사·고전만. 지어낸 통계·가짜 인용 금지. 애매하면 단정 대신 "~라고 알려져 있어요".
- **저작권:** 특정 저작물을 그대로 옮기지 않고 재구성. `source`에 근거를 한 줄로 명시.
- **난이도 차이:** 저학년=1문장 1개념, 문장 15자 내외 지향, 한자어 최소. 고학년=인과·비교·배경까지.
- **분량:** 저학년 200~350자, 고학년 350~600자 목표(엄격한 상한 아님).
- **어조:** 다정하고 호기심을 돋우는 말투. 질문으로 시작해 궁금하게.
- **중복 방지:** 집필 전 `topics.json`을 읽어 **최근 60개 주제/키워드와 겹치지 않는** 새 주제 선정. 4갈래를 고르게 순환.

## 7. 프론트엔드 화면 & UX

극단적 단순화 원칙: **화면은 실질적으로 3개**(홈=오늘 글, 퀴즈, 인쇄). 아카이브·계정·진도 없음.

### 7.1 홈 = 오늘의 신문 1면
- 상단 **제호(masthead)**: 신문 이름(가제) + 발행일 + "제 N 호". 신문다운 세리프 로고(SVG).
- **헤드라인**: 오늘 기사 제목·부제·갈래 배지.
- **난이도 토글**: [저학년 3·4] / [고학년 5·6] 스위치. 선택에 따라 `body.lower`/`upper` 표시.
- **본문**: 문단 렌더링. 본문 속 `vocab` 낱말은 밑줄·색 표시 → 탭/클릭하면 **뜻 툴팁**.
- **읽어주기(TTS)**: 브라우저 내장 음성(Web Speech API, `ko-KR`)으로 본문 낭독. 재생/정지. (무료·오프라인, 읽기 약한 아이 지원)
- 하단 **"퀴즈 풀러 가기"** 버튼.

### 7.2 퀴즈 화면
- 순서: 내용 이해 → 어휘 → 생각 넓히기 → (있으면) 보너스.
- **문항별 즉시 채점**: 정답/오답 표시 + `explain` 해설. cloze는 `acceptable` 정규화(공백·문장부호 제거) 비교.
- 생각 넓히기: 자유 입력 → 제출하면 `modelAnswer` 토글로 "이렇게 생각해볼 수도 있어요" 비교(채점 아님).
- 끝나면 **점수 요약**(예: 내용 3/4, 어휘 2/2) + **도장/별 리워드 애니메이션** + "다시 풀기".
- **저장하지 않음**: 새로고침하면 초기화. 세션 메모리에만 유지.

### 7.3 인쇄용 워크시트
- 버튼 하나로 인쇄 뷰. `@media print` 최적화, A4 1~2장.
- **학생용**: 기사(선택한 난이도) + 문제(정답 숨김) + 빈 답란.
- **교사용(정답지)**: 동일 레이아웃 + 정답·해설 표시.
- 인쇄 전 옵션: 난이도(저/고), 학생용/교사용 선택.

### 7.4 교사용 접근(경량)
- 별도 로그인 없음. `?date=YYYY-MM-DD`로 특정 날짜 글 열람 → 그대로 인쇄 가능.
- 상단에 작은 "인쇄" / "난이도" 컨트롤만. (관리 화면 없음)

## 8. 반응형·접근성·비기능 요구

- **반응형:** 모바일·태블릿·PC. 교실 태블릿/스마트폰에서 편하게.
- **접근성:** 큰 글씨 토글, 충분한 대비, 키보드 조작 가능, TTS 낭독.
- **성능:** 오늘 글 1편 + 앱 셸만 로딩 → 즉시 표시. 총 전송량 작게.
- **프라이버시:** 수집·전송·쿠키 없음(분석 도구도 v1 미포함). 아동 대상이므로 개인정보 0 유지.
- **오프라인/인쇄 대체:** 순수 `file://` 열람은 미보장(정적 호스팅 전제). 오프라인 필요 시 인쇄 워크시트로 대체.

## 9. 매일 밤 자동화 (나이틀리 잡)

### 9.1 트리거
- **클라우드 예약 실행(cron routine)**, 매일 새벽(예: 05:00 KST) 1회.

### 9.2 잡 절차 (멱등·검증 포함)
1. 저장소 최신화(pull).
2. `content/topics.json` 로딩 → 최근 주제·키워드 파악.
3. 4갈래를 순환하며 **겹치지 않는 새 주제** 1개 선정.
4. 스키마(§5.1)에 맞춰 기사·어휘·퀴즈 집필.
5. **자동 검증 스크립트(Node) 통과 필수**:
   - JSON 스키마/필수 필드 채움
   - `answerIndex`가 `choices` 범위 내
   - `ox.answer` 불리언, `cloze.acceptable` 비어있지 않음
   - 금칙어 미포함
   - `date` == 실행일, `issueNo` == 기존 최대+1
   - 검증 실패 시 재생성(최대 N회), 계속 실패면 커밋 중단 + 알림 로그.
6. `content/YYYY-MM-DD.json` 저장, `index.json`·`topics.json` 갱신.
7. `git commit && push` → 호스팅 자동 배포.
8. 실행 결과를 로그로 남김(성공/실패/주제).

### 9.3 아침 검토 안전장치
- `review.html`(로컬/배포): 최근 생성 글을 `source`와 함께 한 화면에 나열 → 사람이 1분 훑고 부적절 항목만 조치.
- (v1은 자동 검증으로 충분. review.html은 선택 안전장치로 포함.)

## 10. 배포

- GitHub 저장소 생성 → 무료 정적 호스팅 연결(Pages 또는 Netlify).
- `main` push 시 자동 배포.
- 나이틀리 잡이 push하면 새 글이 자동 반영.
